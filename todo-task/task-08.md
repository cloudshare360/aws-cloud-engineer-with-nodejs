# Task 08 — Create a JavaScript Learning Plan Schedule from the Tracking Sheet

**Goal:** Turn the Programiz JavaScript tracking sheet into a concrete, day-by-day learning plan you can execute and mark off.

> **Source file:** `programiz-learning/Programiz-JavaScript-Tracking-Sheet.xls`
> Mirrors: `Programiz-JavaScript-Tracking-Sheet.csv` and `.md` in the same folder (same 59 topics, same Estimated Hours).

---

## Step 1 — Read the Tracking Sheet

Open the `.xls` in Excel/LibreOffice. Columns:

| Column | Use |
|---|---|
| Srno, Task, Sub-Task-Level1, Sub-Task-Level2 | What to study |
| **Estimated Hours** | Your workload per topic (total = **83.0 h**) |
| Planned Start / End Date | Fill from the schedule below |
| Actual Start / End Date | Fill as you progress |
| Remarks | Notes, difficulty, links to code you wrote |
| References | Programiz URL for the topic |

> If you cannot open the `.xls`, the `.md`/`.csv` mirrors contain identical data and open anywhere.

## Step 2 — Choose Your Cadence

The 83.0 hours pack into these timelines:

| Cadence | Hours/week | Duration | Best for |
|---|---|---|---|
| **2.0 h × 5 weekdays (Mon–Fri)** ← default plan below | 10 h | **11 weeks** | Working professionals |
| 3.0 h × 5 weekdays | 15 h | ~6 weeks | Focused study |
| 1.0 h/day × 7 days | 7 h | ~12 weeks | Light daily habit |
| 4.0 h × 5 weekdays | 20 h | ~4.5 weeks | Full-time prep |

The schedule below uses the **2.0 h/weekday** cadence.

## Step 5 — Track Progress in the Sheet

For every topic you finish, update the tracking sheet:

1. **Planned Start Date** = the weekday date from the schedule (e.g., Week 1 Monday → your start date)
2. **Actual Start / End Date** = the real dates when you studied it
3. **Remarks** = one line: what clicked, what was hard, link to your practice file

Tip — commit your practice code alongside:

```powershell
# inside your study repo
mkdir js-practice; cd js-practice
git init
git add .
git commit -m "Week 1: JS Introduction practice (#1-#6)"
git push -u origin main
```

## Step 6 — Study Method Per Topic (2.0 h Session)

| Phase | Time | What to do |
|---|---|---|
| Read | ~25 min | Open the References URL / local `index.md` in the topic folder |
| Code along | ~30 min | Type every example yourself in the browser console or VS Code |
| Modify | ~20 min | Change inputs, break things on purpose, observe outputs |
| Mini-challenge | ~30 min | One original snippet using the concept |
| Review + log | ~15 min | Update the tracking sheet row; note anything fuzzy |

> **Local content tip:** each topic already exists in `programiz-learning/javascript/<section>/<topic>/index.md` with images — you can study fully offline.

## Step 7 — Weekly Rhythm

- **Mon–Fri:** scheduled study (2.0 h each)
- **Sat (optional):** review the week — re-do the mini-challenges that felt hard
- **Sun:** rest or get ahead if you fell behind (use the buffer, don't shift the plan)
- Falling behind >3 days? Don't compress — shift the whole schedule right; consistency beats speed.

## Troubleshooting

| Problem | Fix |
|---|---|
| A day's topics overflow (longer than 2.0 h) | Move the overflow to Saturday's review slot, not the next weekday |
| Topic feels too hard (e.g., #23 Prototype, #52 Closure) | Double the session for it; steal time from #59-style light topics |
| Lost the schedule | Regenerate from the CSV: the packing is "fill 2.0 h/day in Srno order" |
| Missed days after Week 5 | Shift start date; the week structure stays valid |
